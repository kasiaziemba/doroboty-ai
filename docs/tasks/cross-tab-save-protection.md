# Cross-tab save protection and release smoke check

Created: 2026-11-12

## Goal

Prevent a second open tab from silently overwriting newer browser-local scenario data, and document what to check immediately after publishing the static build. Both items come from the production-readiness audit (`docs/production-readiness.html`: `concurrent-writes`, `smoke-plan`).

## Context

The whole scenario is saved under one localStorage key. Each tab keeps its own in-memory state and `saveState` writes it in full, so a change made in tab A was lost without notice when tab B saved later. Live cross-tab synchronization stays out of scope.

## Intended behavior

- When another tab of the same origin changes or clears the saved scenario, the current tab shows a status notice explaining that the data changed elsewhere, with a button that reloads the page.
- While the tab is outdated, ordinary actions do not save: they return an alert error and leave form input in place, so nothing is silently discarded.
- Import and reset remain explicit, confirmed replacements and clear the outdated state.
- Same-tab behavior, unreadable-save protection and storage-denial recovery are unchanged.

## Acceptance criteria

- [x] Browser journey with two pages in one context: a save in the second page makes the first page show the notice, refuse a further change with an error and keep the second page's data in storage; reload shows the newer data.

## Risks

- A user with unsaved typing in an outdated tab must copy it before reloading; the notice says so.
- Storage events are not delivered across browsers or devices; that remains a documented limit.
